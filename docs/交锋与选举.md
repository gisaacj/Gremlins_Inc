## 摘要（先读这 6 条）

1. **本次反编译的是客户端程序集，权威服务器引擎不在其中。** 实现 `ISGame` 的类只有一个空壳 `SGame`，`ExecuteGameCommand` / `SendCommand` 方法体为空（`SGame.cs:60-78`）。因此「什么条件触发交锋」「MaxResultValue 怎么算」「谁赢谁付钱」「选举哪一天触发」这类**引擎规则在本代码库中不存在**，本文一律标 `未确认`。
2. **可以权威确认的是三件事**：(a) 三条交锋命令 / 两条选举命令的**字段与字节序**；(b) 客户端为了对齐服务器而**重算**的镜像逻辑（选举加票、票数比较、平局判定、出价上限夹取）；(c) 共享层里真实实现的规则函数（`GMap` 的路径枚举与建筑截断、`GPlayer.PayBribe` / `GetBribe`）。
3. **交锋被拆成两套 UI，由同一个 `ConflictFlag` 字段分流**：`ConflictFlag == true` → `CConflictForm`（固定 2 人，带监狱框）；`false` → `CAuctionForm`（最多 6 人）。见 `CD.cs:9936-9965`。
4. **选举的加票规则可以完整确认**：所有玩家中**罪恶（Malice）最低**的那位额外获得 `ELECTION_VOTE_BONUS = 3` 票；若**全员罪恶相同则没有人获得加票**。平局时在得票最高者中取**罪恶最低**者；若全员票数并列则不产生胜者。见 `CElectionForm.cs:262-304`、`CAvatarForm.cs:589-666`。
5. **掷骰是服务器权威的**：服务器把**预先算好的多个点数**（最多 4 个）一次性发给客户端（`ComRollDice.ResultList`），客户端只负责播动画、然后回一个**下标** `ComRollDiceAnswer.ResultIndex` 表示"用第几个"。客户端无法影响点数。掷骰结果落在 `GPlayer.RollResult`。见 `ComRollDice.cs:528-546`、`CCubeForm.cs:336-366`。
6. **移动的步数不是掷骰，而是打出的行动卡上的 `MovePoints`（1..6）**；路径由客户端枚举并整条上报（`ComMoveStart.CellPath`）；**可以在建筑格提前停下**，这一点有明确代码（`GMap.cs:152-178`）。
