# 《地精公司》（Gremlins, Inc.）回合结构与结算顺序

> 来源：`test/code/Assembly-CSharp/`（dnSpy 反编译，共 1911 个 `.cs`，与 `Assembly-CSharp.csproj` 的
> 1911 条 `Compile` 项**完全一一对应**，无缺失文件）。
>
> **一句话总结**：本次反编译到的是**客户端**程序集；回合阶段枚举 `GTurnPhase` 确实存在且顺序为
> `Begin → Move → UseCard → UseCell`，但**驱动回合的服务器引擎（谁在什么时机设置 `TurnPhase`、扣卡牌价格、
> 重置回合标记、判定选举与胜利）不在本反编译产物内**——`GTurnPhase` 在全部源码中只出现在 `GGame` 的
> 序列化/反序列化里（6 处），`ISGame`/`SGame` 的 `ExecuteGameCommand` 是空方法。因此本文把结论分成
> **「代码可直接证明」**（附代码引用）与 **「未找到/不确定」**（集中列在文末）两部分，不做无依据的补全。
> 能用数据（`DM.cs` 卡牌定义、`data/action_cards.json` 卡面文本）证明的规则，均给出卡名与数值。

## 1. 回合阶段枚举（`GTurnPhase`）

`GServer/GTurnPhase.cs` 全文（去掉 dnSpy 的 Token 注释）：

```csharp
public enum GTurnPhase
{
    Begin,
    Move,
    UseCard,
    UseCell
}
```

即**声明顺序**（也是隐式取值顺序）：

| 值 | 数值 | 含义（按命名） | 证据 |
|---|---|---|---|
| `Begin` | 0 | 回合开始 | `GTurnPhase.cs` |
| `Move` | 1 | 移动 | 同上 |
| `UseCard` | 2 | 使用卡牌 | 同上 |
| `UseCell` | 3 | 结算所在格 | 同上 |

要点：

* **没有 `End` 阶段**。回合结束不是枚举里的一个阶段（也没有 `ComEndTurn` 命令，见 §2）。
* 该枚举通过 `GGame.TurnPhase`（`public GTurnPhase TurnPhase;`）整体序列化下发，说明它是**服务端权威状态**，
  客户端只是接收并展示。
* **不能从本仓库证明**各个阶段之间的转移代码（例如是 `++` 递增还是显式赋值），只证明声明顺序为
  `Begin < Move < UseCard < UseCell`。若以「值越大越靠后」理解，则**出牌阶段（2）先于格子结算（3）**。
  注意：`EAction.UseCellEarly` 虽然名字像「提前结算格子」，但它**只在 `EAction.cs` 里声明、全仓库无使用**
  （含卡牌与格子数据），因此它不能作为顺序的证据（详见 §8 第 1 条）。

## 2. 回合如何开始与结束

### 2.1 结论

* **回合开始**：服务端下发 `ComBeginTurn`，字段只有 `PlayerID`：

```csharp
// ComBeginTurn.Decode
comBeginTurn.PlayerID = gbufferReader.ReadOptimizedUIN("Command = ComBeginTurn.PlayerID");
```

  客户端收到后：切换当前行动者高亮、更新全部卡牌、把「是不是我的回合」状态设为 `true/false`：

```csharp
// CD.onBeginTurn
CD.GameForm.form.SelectActivePlayer(com.PlayerID);
if (com.PlayerID == CD.PlayerID)
{
    UserConfigController.OnBeginTurn();
    CD.GameForm.form.SetStartOfMyTurn(true);
}
else
{
    CD.GameForm.form.SetStartOfMyTurn(false);
}
```

* **回合结束**：**未找到**任何显式「结束回合」的命令或方法。全仓库 grep `ComEndTurn` = 0 个匹配；
  `EndTurn` 只作为**教学断点**存在：

```csharp
public enum ETutorialBreakpoint { None, EndTurn, EnterLocation, PlayCard }
```

  也就是说：服务端结束一个回合后，直接开始下一个 `ComBeginTurn`；玩家视角的「回合结束」是被动的。

* **驱动方法**：**未找到**（见 §0）。本仓库只能给出「玩家在回合内可以做哪些动作、通过哪些命令传给服务端」，
  以及这些命令彼此的顺序约束。

### 2.2 一个回合中玩家可用的动作（客户端 → 服务端的命令）

| 命令 | 关键字段 | 语义 | 证据 |
|---|---|---|---|
| `ComRollDiceAnswer` | `ResultIndex` | 回应服务端的掷骰请求（骰子由客户端物理模拟，结果回报给服务端） | `CCubeForm.NextTurn()`、`CD.onRollDice` |
| `ComMoveStart` | `int CardSlot`、`GUinList CellPath` | **用第 N 张手牌沿这条路径移动** | 见 §3 |
| `ComMovePlayerAnswer`（回应服务端的 `ComMovePlayer`） | `EResult Result` | 回应移动请求 | `ComMovePlayerAnswer.cs` |
| `ComMovePlayer`（服务端→客户端） | `CellID`、`PlayerID`、`TeleportFlag`、`Result` | 棋子移动（客户端播动画并写入 `Player.CellID`） | `CD.onMovePlayer`、`CGameForm.MovePlayer` |
| `ComPlayACardAnswer` | `int CardSlotNum`、`UIN ChaosCardID` | **选择第 N 张手牌出牌（发挥效果）** | 见 §3 |
| `ComSpecialMoveCard` | `CardID`、`MovePoints`、`Reverce`、`PlayerID` | 双向：客户端请求「这张牌怎么走」，服务端回「移动点数/是否反向」，`MovePoints == 0` 表示取消 | `CGameForm.OnCardSelect` / `CD.onSpecialCard` |
| `ComElectionWindowAnswer` | `PlayerID` | 回应选举弹窗 | `CElectionForm.OnCloseClick` |
| `ComConflictWindowAnswer` / `ComJailCardAnswer` / `ComJailDialogAnswer` / `ComSelectOpponentAnswer` / `ComSelectCardsAnswer` / `ComSelectCellAnswer` / `ComSelectCellTypeAnswer` / `ComSelectMFAnswer` / `ComSelectPermanentAnswer` / `ComCardDialogAnswer` / `ComDialogAnswer` | 各自参数 | 各类弹窗/选人/选牌互动 | 命令清单 |

配套的服务端→客户端提示命令（说明回合中会出现「中断式交互」）：
`ComPlayACard`（请你出牌：附带 `GHandCards HandCards`、`CaptionID`、`DescriptionID`、`GStringDict ParamList`、`GUinList ChaosCards`、`Timeout`）、
`ComSelectCards`、`ComSelectCell`、`ComSelectOpponent`、`ComSelectPermanent`、`ComSelectCellType`、
`ComConflictWindow(Update)`、`ComMFWindow(Update)`、`ComDialog`、`ComInfoWindow(Update)`、`ComWriteLog`、
`ComShowCard`、`ComShowDiscard`、`ComResetWaitTimer`、`ComPlayerTimeOut`。

由此可证实的回合内**交互顺序**（而非结算顺序）：

1. 服务端 `ComBeginTurn{PlayerID}` → 该玩家回合开始；
2. 需要掷骰时服务端发 `ComRollDice`（`GIntList ResultList` 可带多项可选结果 = 允许重掷），
   客户端 `ComRollDiceAnswer{ResultIndex}`。**「掷骰在移动之前」是推断**：证据是 a022 的移动分支被写成
   `ROLL(Move)`（即该参数就是「按骰子移动」）、以及 `GPlayer` 上有 `RollResult` / `RollCount` 字段；
   但本仓库不能证明掷骰一定发生在回合最开始（而不是移动那一刻）。
3. 服务端把棋盘/卡牌置为可选（`ComSetGameMode` / `ComEnableBoard` / `ComEnableCards`）；
4. 玩家选牌 + 选路径 → `ComMoveStart{CardSlot, CellPath}`；
5. 移动动画 `ComMovePlayer`、`ComShowCard{CardID, PlayerID, MoveFlag}`；
6. 落入格子后触发格子/建筑效果（表现为 `ComDialog`、`ComSelectOpponent`、`ComConflictWindow`、
   `ComMFWindow`、`ComJailCard`、`ComInfoWindow`、`ComWriteLog` 等一连串弹窗）；
7. 出牌（发挥效果）由服务端 `ComPlayACard` 询问 + 客户端 `ComPlayACardAnswer{CardSlotNum}` 回答；
8. 下一次 `ComBeginTurn`。

> **重要**：第 6、7 步的先后**无法从本仓库确定**。`GTurnPhase` 的声明顺序（`UseCard` 在 `UseCell` 之前）
> 支持「先出牌、后结算格子」，但 `EAction.UseCellEarly` 的存在说明这并非绝对（见 §8）。

## 3. 「用牌移动」与「出牌发挥效果」的区别、以及价格

### 3.1 两种用法在协议层就是两个不同命令

* **用牌移动**：`ComMoveStart{ CardSlot, CellPath }`——客户端在本地算出路径后把**整条路径**发给服务端：

```csharp
// CGameForm.OnCardSelect（EGameMode.MoveSelectCard 分支）
CD.SendCommand(new ComMoveStart
{
    RequestID = this.gameModeRequestID,
    CardSlot = this.getCardNum(card),
    CellPath = new GUinList { List = (list ?? this.SelectedCell.CellPathList) }
});
```

* **出牌发挥效果**：服务端先 `ComPlayACard`（附手牌列表与标题），客户端回答 `ComPlayACardAnswer{ CardSlotNum }`：

```csharp
// CGameForm.OnCardSelect（EGameMode.SelectACard 分支）
int cardNum = this.getCardNum(card);
CD.SendAnswer(new ComPlayACardAnswer { CardSlotNum = cardNum });
CD.selectJailACard = false;
CD.PlayACardForm.Hide();
```

* 服务端用 `ComShowCard` 广播「某玩家打出了某张牌」，其中 **`bool MoveFlag` 明确区分是不是「用于移动」**：

```csharp
// ComShowCard.Decode
comShowCard.CardID    = gbufferReader.ReadOptimizedUIN("Command = ComShowCard.CardID");
comShowCard.PlayerID  = gbufferReader.ReadOptimizedUIN("Command = ComShowCard.PlayerID");
comShowCard.MoveFlag  = gbufferReader.ReadOptimizedBoolean("Command = ComShowCard.MoveFlag");
```

  （客户端 `CGameForm.ShowPlayCard(UIN playerID, UIN cardID, bool moveCard)` **忽略**了 `moveCard` 参数，
  只放音效并显示弃牌，所以这条 flag 目前只体现服务端语义。）

### 3.2 卡面数据本身把两种用法分开写（`[m]` 段落）

`GServer/GActionCard` 上同时有 `int MovePoints`、`int PriceType`/`PriceValue`、`bool SpecialFlag`、
`bool SpecialMoveFlag`。客户端卡牌详情页把描述文本按两个标记切成两段：

```csharp
// CCardDetailsForm.cs
private string instantKey = "[i]";
private string moveKey = "[m]";
...
this.RuleTextPanel2.Active = gCard.SpecialMoveFlag;
if (this.RuleTextPanel2.Active)
{
    string text = TAG.Labels[gCard.DescriptionID];
    text = this.SetCardParams(text);
    if (text.IndexOf(this.moveKey) > -1)
        text = text.Substring(text.IndexOf(this.moveKey) + 3);
```

即：`[m]` 之后是「如果用它移动」的额外规则，而 `SpecialMoveFlag == true` 的卡才有这一段。
从 `data/action_cards.json` 抽出的实例（`{1}` 对应 `Param1`）：

| 卡（Name） | 卡名 | `PriceType/PriceValue` | `MovePoints` | 描述（节选） |
|---|---|---|---|---|
| a015 | Perpetuum mobile | Money / **1000** | 6 | 只有 `[m]` 段：`-{1}$ if you use this card to move.`（`Param1 = 20`） |
| a066 | Fast and fair | Money / **100** | 3 | `Teleport anywhere.` / `[m]` / `When you use this card to move, you can pay {1}$ to change move points to 4.`（`Param1 = 20`） |
| a022 | A poseur | None / 0 | **0** | `Use the Gamble spot mechanic...` / `[m]` / `To use this card to move, roll the dice and move accordingly.` |
| a059 | Second-hand | None / 0 | **0** | `You can play another card.` / `[m]` / `If you use this card to move, choose another player... use it to move.` |

### 3.3 价格在两种用法下是否都付？——**没有找到扣价代码**

* 全部源码中**没有**从 `PriceValue` 扣资源的代码。grep `PriceValue` 的用法只有：卡牌数据初始化
  （`DM.cs`）、mod 覆盖（`CD.cs`）、**显示**（`CACardForm`、`CCardDetailsForm`、`CChaosCardForm`、`GainLogPanel`）、
  以及一个「可用性」判定（见下）。
* `GPlayer.PayResource(...)` 是通用的「把资源从 A 转给 B」的原子操作（含 `ComAnimateResource` 动画与成就判定），
  **本程序集内没有调用者**，也没有任何地方用 `PriceValue` 去调用它 → 卡牌价格的真正扣除在服务端，**未找到**。

能作为**强证据（但不是直接引用的扣价代码）**的两处「可用性」判定：

```csharp
// GPlayer.GetActivePlayCards()：出牌（发挥效果）受价格与所在地限制
if (actionCard.PriceType == GPriceType.Money && actionCard.PriceValue > this.Resources.Money)
    status = GActiveStatus.PassivePrice;
if (actionCard.PriceType == GPriceType.Vote && actionCard.PriceValue > this.Resources.Vote)
    status = GActiveStatus.PassivePrice;
if (actionCard.CellID != this.Game.Game.Map.Cells[this.CellID].CellTypeID)
    status = GActiveStatus.PassiveCell;
```

```csharp
// GPlayer.GetActiveMoveCards()：用牌移动不检查 PriceValue，只有 a015 一个硬编码特例
GActiveStatus status = GActiveStatus.Active;
if (actionCard.Name == "a015" && 20 > this.Resources.Money)
    status = GActiveStatus.PassivePrice;
list.Add(new GActiveCard { ID = ghandCard.CardID, Status = status });
```

第三处证据来自卡牌数据本身：**没有任何一张卡的 `ActionList` 会扣掉自己的 `PriceValue`**。
最典型的是 a015（`PriceValue = Money/1000`、`Param1 = 20`），它的整条动作链里**只出现 20**：

```text
a015 (Perpetuum mobile) => MOVE() > SelectSelf() > OpponentLoseMoney(20)
a066 (Fast and fair)     => Teleport(All) > SpecialMove(20)     // PriceValue = 100
```

即 `PriceValue` 由**引擎**处理（不在卡牌动作清单里），而移动分支的花费写在 `Param1` 并以普通动作表达。

可推出的结论（**标注为推断**）：

1. `PriceValue` 是**「出牌发挥效果」**的价格；`GetActivePlayCards` 会因付不起而把卡置灰（`PassivePrice`），
   而 `GetActiveMoveCards` **完全不看** `PriceValue`。
2. 用牌移动的代价另写在 `Param1` 里：a015 的移动费是 20（且 `GetActiveMoveCards` 用的正是 `20`，不是
   `PriceValue = 1000`——这是最直接的代码证据）；a066 的移动改点数也是 `Param1 = 20`。
3. 因此「移动用法不付 `PriceValue`」是**高置信推断**，但缺少服务端的扣价代码，不能算已证实的规则。
4. `GPriceType` 的完整取值说明价格类型不止钱：`None, Money, Vote, Score, Malice, Income, Term`
   （`GPriceType.cs`）；但上面的可用性判定**只覆盖 Money 与 Vote**，其余类型（Score/Malice/Income/Term）
   的可用性由服务端判断 → 未找到。

### 3.4 用牌移动的路径与点数规则（客户端共享代码，可作权威参考）

`GMap.GetCellPathID(UIN startCellID, GActionCard card, bool inCells)` 是移动可达性的实现：

* 建筑格（`DM.CellTypes[...].BuildingFlag`）允许**中途停留**：把路径截断到该建筑，作为一条额外候选路径：

### 3.5 服务端往返决定移动点数的机制（易错点）

客户端点选一张「不能用普通方式移动」的牌时，会**先把请求发给服务端、等服务端回话**：

```csharp
// CGameForm.OnCardSelect（EGameMode.Move 分支）
bool flag = false;
foreach (GActionItem gactionItem in card.Card.ActionList)
{
    flag = (gactionItem.ActionType == EAction.SpecialMove);
    if (flag) break;
}
if (card.Card.MovePoints == 0 || flag)
{
    this.waitMoveCard = card;
    this.notCellSelect = true;
    this.SpecialCardsDisable = true;
    ...
    CD.SendCommand(new ComSpecialMoveCard { CardID = card.Card.ID, PlayerID = CD.PlayerID });
    return;
}
```

服务端以 `ComSpecialMoveCard{ CardID, MovePoints, Reverce, Timeout }` 回应，客户端把该卡的
`MovePoints` **临时改掉**（`DM.ActionCards[com.CardID].CustomMovePoints = com.MovePoints;`）再选格子；
`MovePoints == 0` 表示取消。因此**卡牌的移动点数是可被运行时改写的**，不能直接拿 `DM.cs` 的静态值当真。

已知需要这条通道的卡（客户端初始化时被显式复位，`CD.cs` L10682-10687）：

```csharp
DM.ActionCards["E3C036E3076F010F"].MovePoints = 0;   // a022 A poseur
DM.ActionCards["E4724DE30715131C"].MovePoints = 0;   // a059 Second-hand
DM.ActionCards["D84F5BE30719B823"].MovePoints = 3;   // a066 Fast and fair
DM.ActionCards["E3C036E3076F010F"].CustomMovePoints = 0;
DM.ActionCards["E4724DE30715131C"].CustomMovePoints = 0;
DM.ActionCards["D84F5BE30719B823"].CustomMovePoints = 0;
```

## 8. 容易搞错的顺序约束

1. **`GTurnPhase` 的顺序是 `UseCard(2)` 在 `UseCell(3)` 之前**，即按枚举声明「先出牌、后结算格子」。
   但请注意两点反证：
   * `EAction.UseCellEarly`（"提前使用格子"）**只作为枚举项存在**——全仓库（含 `DM.cs` 全部卡牌与格子数据）
     没有任何一处使用它，因此**不能**拿它来证明「格子效果可以提前」；
   * `EAction.IgnoreCell`（**11 张卡**：a023/a046/a047/a048/a051/a052/a097/a098/a100/a128/a160）可以**跳过**格子效果。
   → 结论只能写成：**枚举声明顺序是「先牌后格」，实际的先后由服务端决定，本仓库无法证明。**
2. **永久卡/角色能力是「内联钩子」，不是独立阶段**——它们在被触发的那一刻被求值，而不是在回合末尾统一结算。
   最直接的证据是 `GetBribe()` 与 `GetIncome()` 把永久卡效果算进函数返回值本身：

```csharp
// GPlayer.GetBribe()：别人手上的 Perm_Bribe 直接加进你的贿赂额
foreach (GPlayer gplayer2 in this.Game.Players.Values)
{
    if (gplayer2.PlayerID != this.PlayerID && gplayer2.GetPermanentAbilityCount(EAction.Perm_Bribe) > 0)
        num += gplayer2.GetPermanentAbilityCount(EAction.Perm_Bribe);
}
```

```csharp
// GPlayer.GetIncome()
int num = this.Resources.Income;
num += this.GetPermanentAbilityCount(EAction.Perm_Income);
```

   同理 `Perm_BribeSkip`（"借口编造器"，见 `PayBribe`）是在**付贿赂的过程中**掷骰判定的。
   → 实现时**不能**把「钩子」做成回合末尾的一个阶段。
3. **「额外一张牌」的发放时机是「出牌之后、同一地点」**（a124 原文：
   `After playing a card for action, you can play another card in the same place.`），
   所以额外牌的插入点在 `UseCard` 阶段内部，而不是等 `UseCell` 之后再补。
4. **有些卡必须在客户端与服务端之间往返才能确定移动点数**（`MovePoints == 0` 或含 `EAction.SpecialMove`
   → `ComSpecialMoveCard` 往返，见 §3.5）。静态读 `DM.cs` 的 `MovePoints` 会得到错的答案；
   `CustomMovePoints` 会覆盖 `MovePoints`。
5. **出牌受所在地约束**：`card.CellID == Map.Cells[CellID].CellTypeID`（否则 `PassiveCell`），
   而用牌移动不受此限。
6. **付得起与否只挡住「出牌」不挡「移动」**（Money/Vote 两种价格），且 a015 是唯一在移动时也检查钱（≥20）的卡。
7. **移动路径是客户端算好整条发给服务端的**（`ComMoveStart.CellPath`），服务端只做校验/结算；
   同一终点的多条路径由 `GMap.CheckCellPath()` 打分挑选。顺序约束：路径必须在 `ComMoveStart` 里一次给全。
8. **回合中没有 `EndTurn` 交互**：棋盘/卡牌的可用性由 `ComEnableBoard`/`ComDisableBoard`/
   `ComEnableCards`/`ComDisableCards`/`ComSetGameMode` 单独控制；玩家不会（也无法）主动「结束回合」。
9. **`AdditionalTurn` 用正负号表示「欠的回合」与「跳过的回合」**（§5.2），不要用两个字段。
