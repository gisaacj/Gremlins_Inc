# 局域网联机排查

> 这份文档是"手机 APK 连不上服务端"的排查手册。
> 用户实测：**"我装了 apk 但是没法连接 输入服务器地址一直无法连接"** ——
> 下面是当时查出的两个真实原因，以及以后遇到同类问题的排查顺序。

---

## 一、两个真正的原因（都已修）

### 原因 1：Android 9+ 默认禁止明文 HTTP（**代码问题**）

`AndroidManifest.xml` 里**没有** `usesCleartextTraffic`，而
`targetSdkVersion = 34`。Android 从 API 28 起默认
`cleartextTrafficPermitted = false` —— 也就是说**任何 `http://` 请求都会被系统拦掉**，
而我们的服务端就是 `http://192.168.x.x:3000`（局域网没有 TLS）。

表现：socket.io 连接直接被阻断，界面只会显示"一直无法连接"。

修法（两处，缺一不可）：

```xml
<!-- client/android/app/src/main/AndroidManifest.xml -->
<application
    android:usesCleartextTraffic="true"
    android:networkSecurityConfig="@xml/network_security_config"
    ...>
```

```xml
<!-- client/android/app/src/main/res/xml/network_security_config.xml（新增） -->
<network-security-config>
    <domain-config cleartextTrafficPermitted="true">
        <domain includeSubdomains="true">localhost</domain>
        <domain includeSubdomains="true">127.0.0.1</domain>
        <domain includeSubdomains="true">10.0.2.2</domain>
    </domain-config>
    <base-config cleartextTrafficPermitted="true">
        <trust-anchors><certificates src="system" /></trust-anchors>
    </base-config>
</network-security-config>
```

> ⚠️ 改完必须**重新编译 APK**，光热更新不行（这是原生清单）。
>
> ⚠️ 私网网段（10./172.16./192.168.）无法用 `domain` 通配表达，
> 所以 `base-config` 也放开了明文。这是局域网内部使用的取舍；
> 若将来上公网，应改 HTTPS 并把 `base-config` 收紧为 `false`。

### 原因 2：Windows 防火墙没有放行端口（**环境问题**）

`Get-NetFirewallRule` 查下来：**没有任何放行 3000 端口的入站规则**，
`node.exe` 也不在允许列表里。

关键点：**Windows 防火墙默认不拦"本机访问本机"**，
所以"在电脑浏览器打开 `http://127.0.0.1:3000` 正常"**完全不能证明手机能连上**。
手机是从**外部**连进来的，会被入站规则丢掉。

修法（一条命令，需管理员）：

```powershell
# 以管理员身份运行 PowerShell
powershell -ExecutionPolicy Bypass -File tools\open-firewall.ps1
```

脚本会：
1. 添加入站规则 `Gremlins Inc Server (TCP 3000)`（仅 Private/Domain）
2. 打印本机所有局域网 IP，直接告诉你手机上该填什么

> ⚠️ 这个脚本**刻意写成纯 ASCII**：Windows PowerShell 5.1 按 ANSI 读取 `.ps1`，
> 中文会变乱码并破坏字符串字面量（我第一版就踩了这个坑）。

## 二、正确操作顺序

```powershell
# 1) 在电脑上启动服务端（会同时把网页版托管在 3000 端口）
cd E:\code\小魔怪-push
npm run start:server          # 或开发用 npm run dev

# 2) 确认监听在 0.0.0.0（不是 127.0.0.1）
#    启动日志应出现：Server listening on http://0.0.0.0:3000

# 3) 放行防火墙（一次即可，需管理员）
powershell -ExecutionPolicy Bypass -File tools\open-firewall.ps1

# 4) 查本机 LAN IP（脚本会打印；也可手动看）
ipconfig | Select-String 'IPv4'
```

然后在手机 App 的「服务器」里填：

```
192.168.x.x:3000        ← 只填 IP:端口 即可（会自动补 http://）
```

**注意**：
- 只填 IP 和端口，别填 `localhost`、别填 `127.0.0.1`（那指的是手机自己）
- 手机与电脑必须在**同一个 WiFi / 同一网段**
- 服务端 `HOST` 默认就是 `0.0.0.0`（`server/src/index.ts`），不要改成 `127.0.0.1`

## 三、逐层排查表

按顺序试，哪一层断了就是那个问题：

| 步骤 | 怎么做 | 正常表现 | 断了说明 |
|---|---|---|---|
| 1 服务端在跑 | 电脑浏览器开 `http://127.0.0.1:3000/api/health` | `{"status":"ok",...}` | 服务端没启动 / 端口被占 |
| 2 服务端绑对外 | 看启动日志 | `listening on http://0.0.0.0:3000` | 被改成了 `127.0.0.1` |
| 3 局域网可达 | 电脑浏览器开 `http://192.168.x.x:3000/api/health` | 同上 | 电脑本身网络有问题 |
| 4 防火墙放行 | `tools\open-firewall.ps1` | 提示 added/enabled | 没以管理员运行 |
| 5 手机同网段 | 手机 WiFi 设置里看 IP 是否 `192.168.x.*` | 与电脑同前缀 | 连了别的 WiFi / 热点 |
| 6 App 内地址 | 填 `192.168.x.x:3000` | 状态变"已连接服务器" | 填错 / 多了 `http://` 之外的东西 |

> 第 1~3 步**在同一台电脑上做，绕不过防火墙**，所以第 4 步必须单独确认。

## 四、App 现在会怎么提示

以前 `connect_error` **完全没被处理**，玩家只能看到"正在连接服务器…"一直转。
现在 `client/src/store/game.ts` 会按错误类型给出可读提示，并带上目标地址：

```
无法连接 http://192.168.1.10:3000
连接超时：确认手机与电脑在同一 WiFi、IP 没填错、电脑防火墙放行 3000 端口
```

错误分派逻辑：

| 触发条件 | 提示 |
|---|---|
| `cleartext` / `not permitted` | 明文 HTTP 被系统拦截（自编译包要确认清单里开了 `usesCleartextTraffic`） |
| `timeout` / `timed out` | 连接超时 → 查 WiFi / IP / 防火墙 |
| `refused` / `ECONNREFUSED` | 对方拒绝 → 服务端没起或端口不对 |
| `ENOTFOUND` / `getaddrinfo` | 地址解析失败 → IP 格式不对 |
| 其它 | 原样显示错误信息 |

## 五、为什么测试没拦住这个 bug

诚实记录：**5 个矩阵 + 44 个专项测试全部通过，但手机依然连不上。**
原因是这些测试都在**引擎层**（纯逻辑），而这两个原因分别是

- **原生清单配置**（Android 层）
- **宿主防火墙**（环境层）

两者都在测试覆盖范围之外。已做的改进：
1. 把原因写进本文档，并把防火墙脚本纳入仓库
2. App 内不再"静默重试"，而是把真实错误显示出来
3. `AndroidManifest.xml` 里加了注释说明为什么必须有那两行

**仍然没有**的是：APK 层的自动化验证（例如"装到模拟器里连一次"）。
如果这类问题再发生，建议加一条模拟器冒烟测试。
