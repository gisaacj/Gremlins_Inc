## 0. 阅读约定

### 0.1 资源符号

| 符号 | 字段名 | 中文 | 本文用词 |
|---|---|---|---|
| `$` | `Money` | 金币 | 金钱 |
| `&` | `Vote` | 选票 | 选票 |
| `\|` | `Income` | 收入 | 收入 |
| `*` | `Score` | 威望分数 | **齿轮** |
| `^` | `Malice` | 邪恶 | **罪恶** |
| `~` | — | 贿赂 | 贿赂 |
| `#` | — | 监狱经验 | 监狱经验 |
| `(e)` / `(B)` | — | 收入 / 贿赂基数 | 收入 / 贿赂 |

`Income`（收益）与 `Outcome`（代价）都是 `GResource`，六个字段：
`Money / Vote / Score / Malice / Term / Income`。
本文写作 `收益[Money+50, Score+2]` 这种形式；`Term` 单独写作「刑期」。

### 0.2 `{1}`..`{6}` 占位符 → `Param1..6`

**厄运牌 / 监狱牌 / 暴乱牌**：描述文本里的 `{n}` 取 **`ParamN`**（客户端代码
`CJailCardForm.cs:340-345`、`JailCardDetailsPanel.cs:84-89` 等直接做 `Replace("{n}", ParamN)`）。
本文已就地替换成实际值。

**角色能力**：规则文本里的 `{n}` 取 **`ActionParams[n+1]`**（`ActionParams[0]` 是能力名 UIN、
`ActionParams[1]` 是规则文本 UIN，数字参数从索引 2 开始）。
本文对每条能力都给出「参数映射」表，明确列出 `{n} → 值`。

> ⚠️ **两处映射例外**（原版数据缺陷，非本文笔误）：
> * `Thief_Pickpocketing`（扒窃）文本写 `{2}-{3}`，但数值 `5, 25` 落在 `ActionParams[3], [4]`。
> * `Engineer_Golden_Thumb`（金科玉律）文本写 `{1}*` `{2}*`，数值 `5, 1` 落在 `ActionParams[2], [3]`。

### 0.3 `ActionParams` 里的 16 位十六进制串 = UIN 的十六进制写法

```
A1F44CE0070E5A07  --int(hex,16)-->  11670037059498564103  -->  CellType = Astral（天界）
D9E6618D5FA10DC2  --int(hex,16)-->  15701344410696486338  -->  文本 = 「+1^、监狱刑期：+1次走牌」
```

本文动作链里，能解析的十六进制参数已解析为**格子类型名**或**提示语文本**。

### 0.4 动作链记法

`动作名(参数) -> 动作名(参数)`。参数里：
* 纯数字字符串 = 数值；
* `Malice 10` = 以对方罪恶为基数 ×10；
* `Percent 50` = 按目标当前资源的 50% 计；
* `Bribe 1` = 以贿赂值为基数 ×1；
* `Arrest` = 付不出则逮捕；
* `GetHalf` = 一半归发起者；
* `Invert` = 方向反转（对方付给我）。

### 0.5 符号「⚠️ 中文描述为空」

strings 表里 `DescriptionID` 对应文案为空的卡，其效果**只由 `Income`/`Outcome` 数值实现**，
没有 `ActionList`，游戏内是"看图领资源"的卡。这类卡在本文中以「⚙️ 数值卡」标注。

## 1.3 厄运机制 ✅（可读客户端代码）

### 1.3.1 何时抽厄运

📖 依游戏内百科与格子类型数据，厄运在下列时机降临：

1. **停留在「厄运」格子**（`GCellType.Misfortune`）✅ — `maps.json` 中「Normal」图有 5 个厄运格
   （`Cell27 / Cell30 / Cell44 / Cell60 / Cell62`），「Colony」图有 1 个（`Cell53`）。
   格子的 `DescriptionID` 文案即：「经过此站点时，你将遭遇厄运。」
2. **经过「厄运」格子**（不停留）📖 — 见 `Merchant_Stop` 能力的反例说明：
   「你可以停在厄运站点且不遭遇厄运」→ 反证"默认经过/停留都会遭遇"。
   教程文案也明确：「哪怕只是经过，倒霉事也会找上你。」
3. **冒险站点（Risk）/ 赌博站点（Gamble）掷骰** 📖 —
   「冒险站点及赌博站点的掷骰子也有可能引发厄运。」
4. **在冒险站点买保险** 📖 — 成就文案：「通过在冒险站点购买保险使其他玩家遭遇厄运。」
   （即：把厄运"转嫁"给别人）
5. **卡牌直接引发**（`OpponentGetMisfortune` 原语，共 7 处调用点，含监狱牌 `t011 监狱电报`）
6. **监狱牌 `t011 监狱电报`**：选一个对手，你从 2 张厄运里挑 1 张给他

### 1.3.2 厄运是谁选的？——**"对手从最上面 N 张里挑" 规则确实存在** ✅

`GConst.cs:69`：

```csharp
public int MF_SELECT = 2;
```

`GConst.cs` 里 `MF_SELECT` 的用途在 `ModItemView.cs:63` 与 `DefValues.cs:84` 得到确认，
是可被 mod 覆盖的常量。strings 表对它的解释是**明文**的（键 `13099445238116235306`）：

> 中文：`玩家的对手根据需要选择的厄运数量`
> 英文：`Number of Misfortunes from which player's opponent makes the choice when required`

因此：

| 情形 | 谁选 | 可选张数 |
|---|---|---|
| 默认（你踩到厄运格） | **你的对手**（`MF_SELECT = 2`） | **从最上面 2 张中挑 1 张** |
| 恶魔 `Damned_Connections`（暴乱关系） | 你（若你的罪恶最高） | 从 **2** 张中挑 1 张（能力 `Param1 = 2`） |
| `m038`/`m021` 一类"自己选"的文案 | 你自己 | 文案写「从牌库中剩下的所有厄运中选」 |
| 监狱电报 `t011` | 你（给对手选） | 从 **2** 张中挑 1 张（`Param1 = 2`） |
| 恶魔 EVENTS 规则（`Damned` 角色 `Description`） | 恶魔自己 | 「picks 2 topmost and chooses one」 |

**恶魔（The Damned）的强力之处**正是把"对手替你选"改成"自己从最上面 2 张里选"，
同时 `Damned_Connections` 让"经过厄运格"时也能自选。

界面文案（strings 表）佐证这一流程：
* `12289403523549107613`：`厄运挑选人是...` / `The Misfortune is chosen by...`
* `12242257784244932025`：`谁选择你的厄运？` / `Who chooses the Misfortune for you?`
* `18002835586799766913`：`选择将发生在你身上的厄运。`
* `18023198423281765920`：`{N1}为{N2}选择了厄运。`

### 1.3.3 厄运牌会不会回到牌库？——**会，整副重洗** ✅

`Assembly-CSharp/GServer/GGame.cs:708-769`（`nonlockedMFPickCard()`）**完整实现**：

```csharp
private UIN nonlockedMFPickCard()
{
    if (this.MFCDeck.Count == 0)
    {
        List<UIN> list = new List<UIN>();
        List<GMisFortuneCard> list2 = DM.MisFortuneCards.GetList();
        list.Clear();
        for (int i = 0; i < list2.Count; i++)
        {
            int deckCount = list2[i].DeckCount;      // 每张卡按 DeckCount 重复入池
            if (this.MFCardsModified != null && this.MFCardsModified.ContainsKey(list2[i].ID))
                deckCount = this.MFCardsModified[list2[i].ID].DeckCount;
            for (int j = 0; j < deckCount; j++) list.Add(list2[i].ID);
        }
        // 洗牌：随机数排序
        UIN[] array = (from x in list orderby GGame.GetNextInt32(this.rnd) select x).ToArray<UIN>();
        for (int k = 0; k < array.Length; k++)
        {
            if (this.Players.Count < 5 || !(array[k] == "F7C040EC0741FE1C"))  // ← 5 人以上剔除「丢失的债券」
                this.MFCDeck.AddFirst(array[k]);
        }
    }
    UIN value = this.MFCDeck.First.Value;   // 取最上面一张
    this.MFCDeck.RemoveFirst();
    if (this.MFCDeck.Count == 0)            // 抽完立刻重洗（"预先重洗"）
    {
        ... 同上，重新构造并洗入整个牌库 ...
    }
    return value;
}
```

由此得到的**权威规则**：

| 问题 | 答案 |
|---|---|
| 牌库初始构造 | 遍历全部 40 张，**按 `DeckCount` 重复入池**（全部为 1 → 40 张），随机洗牌 |
| 抽取方向 | 从**队首**取（`MFCDeck` 是 `LinkedList<UIN>`，`AddFirst` 洗入，`First` 取出） |
| 厄运用完一张后回不回牌库？ | **不回。** `RemoveFirst()` 后不再放回 |
| 牌库空了怎么办？ | **整副重洗**：把全部 40 张重新洗成新牌库 |
| 何时重洗？ | ① 首次抽牌且牌库空；② 抽完当前最后一张后**立即**预洗（所以游戏逻辑上永远抽得到牌） |
| **玩家数 ≥ 5 的特殊规则** | 🚩 **`m029 丢失的债券`（ID 十六进制 `F7C040EC0741FE1C`）被剔除，不入牌库** |
| 公开信息 | `MFPickCard()` 每次抽取后广播 `ComUpdateMFCount { Count, FirstID }` → 所有玩家能看到**牌库剩余张数与最上面一张** |
| 一次性抽多张 | `MFPickCards(int number, bool distinct)`；`distinct=true` 时保证抽到的牌互不相同 |

📖 strings 表（键 `13508458462757269667`）与此完全一致：

> 中文：`用过的厄运会被丢弃。所有厄运都用完后，丢弃的牌堆将重洗，成为一整副新卡牌。`
> 英文：`Each Misfortune that happens is discarded from the Misfortune Deck. Once the deck runs out, it is reshuffled.`

**可选局设** 📖：
* 键 `18433224562095321882`「显示即将来临的厄运」/ `17280303531808956443`：
  「通过该选项，所有玩家均可以看到一整副厄运卡牌中最顶部的厄运卡牌。」
  → 开启后 `ComUpdateMFCount.FirstID` 对所有人可见。

## 2.3 监狱机制

### 2.3.1 每个监狱回合抽几张？——**2 / 3 / 4 张（随监狱等级递增）** ✅

`Assembly-CSharp/GServer/GPlayer.cs:181-193`：

```csharp
public int GetJailCardLimit()
{
    int num = 2;
    if (this.JailRank >= 2) num++;   // JailRank 2,3 → 3 张
    if (this.JailRank >= 4) num++;   // JailRank 4   → 4 张
    return num;
}
```

客户端 UI 完全一致（`JailRankDetailsPanel.cs:106-117` 的 `GetJailRankCards`，

| 0 | **新手** / Novice | **2** | 5 |

📖 strings 表对三个常量的解释（键 `17711196595209776441` / `14252432248005970746` / `13099510818241151291`）：

| 常量 | 值 | 含义 |
|---|---|---|
| `JAIL_RANK_1_TERM` | 5 | 掷出 **1-2** 时玩家必须在监狱服刑的走牌数 |

### 2.3.3 监狱表现（Behaviour in Jail）与监狱经验 📖

每次服刑走牌，玩家**主动选择**本次的监狱事件：

| strings 键 | 文案 |
|---|---|
| `13469058707221126632` | 入狱后的每次走牌中，你可以选择要发生在你身上的监狱事件。 |
| `18080744220255395266` | 如果选择**表现消极**，则有机会**赢取资源**以及加快提高**监狱等级**。但是，获得邪恶和在监狱里多待一个回合的机会也会增加。 |

**因此"抽几张监狱牌"的完整语义是**：
1. 服刑回合开始 → 玩家选择**表现**（积极 / 平平 / 消极）→ 决定本回合可抽的卡池（按 `Karma` 过滤）

   `if (this.JailRank < 4) this.JailRank++;`）
5. rank 5（老大）的特殊加成 📖（键 `18137095662428311761`）：`每获取 #3 就将拥有 *1。`

   rank 5 之后 `GetTermLimit() = 3`（**刑期反而最短**）—— 这是"以监狱等级为豪"的玩法核心。

### 2.3.5 监狱牌回不回牌库？——**回，整副重洗** ✅

`Assembly-CSharp/GServer/GGame.cs:824-860`（`JailPickCard()`）：

```csharp
public UIN JailPickCard()
{
    lock (this.jCDeckLocker)
    {
        UIN value = this.JCDeck.First.Value;
        this.JCDeck.RemoveFirst();
        if (this.JCDeck.Count == 0)
        {
            List<UIN> list = new List<UIN>();
            List<GJailCard> list2 = DM.JailCards.GetList();
            for (int i = 0; i < list2.Count; i++)
            {
                int deckCount = list2[i].DeckCount;
                if (this.JailCardsModified != null && this.JailCardsModified.ContainsKey(list2[i].ID))
                    deckCount = this.JailCardsModified[list2[i].ID].DeckCount;
                for (int j = 0; j < deckCount; j++) list.Add(list2[i].ID);
            }
            UIN[] array = (from x in list orderby GGame.GetNextInt32(this.rnd) select x).ToArray<UIN>();
            for (int k = 0; k < array.Length; k++) this.JCDeck.AddFirst(array[k]);
        }
        result = value;
    }
}
```

### 3.3.1 怎么获得 / 怎么打出？——**共享池，先抢先得，不在手牌里** 📖

**结论**（📖 全部来自游戏内文案，`GChaosCard` 类本身不带"归属玩家"字段可作旁证）：

1. **不在手牌里、不是个人牌堆**。6 张暴乱卡是**全体共享的公开池**，面板上以
   `CD.ChaosCardList`（`Images/c` 六张图）展示（`CD.cs:4966-4967`、`CGameForm.SetChaosCards()`）。
   `GChaosCard` 结构上**没有 `DeckCount`、没有 `Owner`** → 与"每张全局唯一"一致。
2. **使用时机**：轮到你的走牌内、且你**人在对应建筑**（`CellID` = 地狱 / 天界 / 工厂）。
3. **不能用于移动**，只能作为**行动**打出（明文文案）。
4. **先抢先得**：一张被任何人打出后**永久消失**，本局不再可用。这正是"阻止对手用某张卡"的策略来源。
5. **代价是即时支付的**（`PriceType` / `PriceValue`）：`c002 c005` 付 **10 选票**；
   `c003 c004` 付 **1000 金钱**；`c006` 付 **2000 金钱**；`c001` 不付钱但要**牺牲一张已激活的永久卡**。
   `CChaosCardForm.cs:713-731` 显示价格不足时置灰（`PriceNoneImage`）。
6. **局设开关**：与角色能力一样，暴乱卡可按局开关（`13557320954448735085`
   「角色技能是一种附加游戏规则……（正如暴乱卡牌一样）」）。
7. **`SpecialFlag`** → 见 `c001` 说明：**"卡面显示特殊规则角标"的开关**，
   即该卡除价格外还有必须阅读的额外使用条件。

### 3.3.2 `SpecialFlag` 到底是什么 ✅

`GChaosCard.cs:313` `public bool SpecialFlag;`
唯一的运行时用途在客户端：
```csharp
// CChaosCardForm.cs:757
this.SpecialIcon.Active = card.SpecialFlag;
```
对比行动卡：`CACardForm.cs:1440` → `this.SpecialIcon.Active = (!card.PermanentFlag && card.SpecialFlag);`
`CCardDetailsForm.cs:409-411 / 533-535` → `if (gCard.SpecialFlag) this.RuleTextPanel1.Active = true;`

所以：
* **`SpecialFlag = true`** → 卡面画"特殊"角标 + 详情面板展开规则文本区
* **数据事实**：6 张暴乱卡里**只有 `c001 供奉`** 为 `true`（因为它有一句额外的使用条件），
  其余 5 张为 `false`（只需付费 + 读数值收益）
* ⚠️ **它不是"能否打出"的开关**，也不是"是否是特殊牌"的类型标记。
