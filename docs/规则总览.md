### 1.8 哪些是"每局可配置"的（重要）

`GConst` 只是**默认值**。上面这些参数在 `GGame` 里都有对应的**实例字段**，
会被序列化进存档/对局，因此**整局内可被房主配置或 mod 覆盖**
（实现在 `CD.cs` 的 `SetConstMod` 路径：`if (name == "INITIAL_MONEY") DM.Const.INITIAL_MONEY = mod.Value;`）：

```csharp
// GGame.cs —— 每局实例字段（不是常量）
public int INITIAL_MONEY;            public int INITIAL_INCOME;
public int ELECTION_DELAY;           public int INITIAL_BRIBE;
public int MALICE_FOR_BRIBE;         public int ELECTION_VOTE_BONUS;
public int ELECTION_SCORE_BONUS;
public int JAIL_RANK_1_TERM;  public int JAIL_RANK_2_TERM;
public int JAIL_RANK_3_TERM;  public int JAIL_RANK_4_TERM;
public int JAIL_RANK_5_TERM;
public int MF_SELECT;                public bool RandomMap;
public bool ShowTopMF;
// 以及可替换的数据：CellMod / CharMod / ActionCardMod /
// JailCardMod / MFCardMod / ChaosCardMod / PlayerMod / GlobalMod
```

**实现建议**：把这些做成 `GameConfig` 对象，而不是散落的常量（原版就是这么做的）。

其中 `ShowTopMF` 值得注意——它与"厄运牌是否公开顶牌"有关，
会影响「停留厄运格由对手挑牌」这类机制。

## 二、贿赂（`GPlayer.GetBribe()` / `PayBribe()`）
### 2.1 贿赂额计算

```csharp
int num = DM.Const.DEFAULT_BRIBE;                    // 20
if (InitialBribe != 0) num = InitialBribe;           // 角色可覆盖（无家可归者）
else if (DEFAULT_BRIBE != INITIAL_BRIBE) num = INITIAL_BRIBE;

if (CharPerks && 角色 == "Homeless")
    num = GetCharacterAbilityParam(Homeless_Smooth_Sailing, num / 2, 2);
    //                                    ↑ 默认值 num/2 = 10

if (CharPerks && 角色 == "Judge")
    num += Malice / param(Judge_Servant_Of_Justice, 2, 3) * param(..., 1, 2);
    //   ↑ 检察官：每 param3 点罪恶 → +param2（默认 每2点罪恶 +1）
else
    num += Malice;                                    // 其他人：+1 罪恶 = +1 贿赂

// 镇长的「呼吸税」（政治家能力 Politician_Breathing_Tax）
if (任意玩家.Governor && 该玩家是 Politician 且有能力)
    num += param(Politician_Breathing_Tax, 5, 2);     // 默认 +5

// 其他玩家持有的提高贿赂永久卡（Perm_Bribe）
foreach (其他玩家 p) if (p.Perm_Bribe > 0) num += p.Perm_Bribe;
```

**结论**：`贿赂 = 基数 + 罪恶`，其中检察官把"每点罪恶+1"改为"每 N 点罪恶+1"。

### 2.2 支付与罚则

```csharp
int malice = MALICE_FOR_BRIBE;                        // 1
// 「借口编造器」Perm_BribeSkip：1d6 > 3（即 4/5/6）→ 完全免付，返回 0
if (Perm_BribeSkip > 0 && rnd.Next(1, 7) > 3) return 0;

// 无家可归者「一帆风顺」：**覆盖的是罪恶值**，不是贿赂额
if (角色 == "Homeless") { int p = param(Homeless_Smooth_Sailing, 0, 3);
                          if (p != 0) malice = p; }

int bribe = GetBribe();
BribeMalice = 0;
if (Double) {                                       // 停留贿赂格 → 双倍
    if (bribe > Money) BribeMalice += malice;       // ← 双倍前先判一次
    bribe *= 2;
}
if (bribe > Money) {                                // 付不出
    bribe = Money;                                  // 付光所有钱
    BribeMalice += malice;                          // +1 罪恶（**固定，不是每点未付**）
}
Money -= bribe;
```

**关键更正**（对照我之前的网页实现）：

1. 罪恶是**每次付不出 +1（固定）**，不是"每点未付贿赂 +1"。
2. `Perm_BribeSkip` 是 **1d6 ≥ 4**（50%），不是无条件的 50% 随机。
3. 无家可归者「一帆风顺」覆盖的是**罪恶值**，贿赂额用的是 `DEFAULT_BRIBE/2`。
4. 双倍贿赂分**两段**判定：先按原值判一次，再按双倍值判一次，可能 +2 罪恶。
5. **贿赂金不给镇长**（从玩家扣除，即归银行）。镇长另有"收受已付贿赂"的机制。

## 四、监狱 rank 系统（`GPlayer.GetTermLimit()` / `GetJailCardLimit()`）

```csharp
GetTermLimit():  JailRank 0→JAIL_RANK_1_TERM(5)
                 1→7   2→8   3→10   4→3
GetJailCardLimit(): int n = 2;
                    if (JailRank >= 2) n++;      // 3
                    if (JailRank >= 4) n++;      // 4
```

即：**每个服刑回合可抽 2/2/3/3/4 张监狱牌**（rank 越高抽得越多），
升级所需经验 5/7/8/10/3。**我之前的实现（1 张/回合、term-=1）是错的。**

⚠️ 这里容易混的一点：`GetTermLimit()` 返回的是**监狱经验的升级门槛**，
不是"被捕时判的刑期"。被捕时判的刑期来自**监狱格的骰子表**（2/3/4 次走牌）。
详见下文第 §六 节。

## 五、建筑的"每次到访一次" —— ⚠️ 需要降级为待确认

`GPlayer` 上有这 11 个字段：

```
BankVisited  OfficeVisited  PlantVisited  DumpVisited  MarketVisited
JailVisited  InfernoVisited CasinoVisited CourthauseVisited
TreasureVisited  AstralVisited
```

**但是**：在**整个反编译程序集**里 grep，这 11 个字段**除了声明处之外没有任何读写**，
而且**没有参与 `Serialize()`**。

```
BankVisited 命中 1 处：GPlayer.cs:1880  public bool BankVisited;   ← 只有声明
```

所以它们只能说明"**原作者打算做**每建筑一次的限制"，**不能作为已验证的机制**。

真正**参与序列化**（因而确实随对局状态走）的计数器是这几个：

```csharp
// GPlayer.Serialize
bw.Write(this.JailTerm);          bw.Write(this.JailKarma);
bw.Write(this.InfernoCounter);    bw.Write(this.AstralCounter);
bw.Write(this.TreasureTurn);
// GGame.Serialize
bw.Write(this.OfficeCounter);
```

它们在客户端同样是"只序列化、无判读"——**具体粒度（每次停留一次？
每回合一次？）由不在本程序集里的服务端执行器决定**。

**结论**：可以确定的是"每次停在建筑上会弹一次接受/拒绝选择"；
"同一回合能否重复使用同一建筑"**未确认**。实现时建议先按**每回合一次**做，
并把这个开关做成配置项。

## 六、监狱：两套必须区分的数值 ⚠️

之前我把它们混为一谈，这里更正：

| 字段 | 含义 | 显示 |
|---|---|---|
| `GPlayer.JailTerm` | **剩余刑期** | 头像上的数字；`> 0` 表示在狱中 |
| `GPlayer.Resources.Term` | **监狱经验**（当前等级内的进度） | `CJailStatsForm` 用 `#"+(limit-Term)` 显示"升级还需" |

- 等级 `JailRank` 0..4，名称：**新手 Novice / 农民 Peasant / 恶棍 Thug /
  二把手 Right-Hand Man / 老大 The Don**
- 升级所需经验：**5 / 7 / 8 / 10 / 3**（对应 `JAIL_RANK_1..5_TERM`）
- 升到"老大"（rank 4）之后，**每满 3 点经验 → +1 齿轮**
- 每回合的候选监狱牌数 `GetJailCardLimit()` = **2 / 2 / 3 / 3 / 4**（按 rank）
- 每回合开始先选"表现"（积极/平平/消极），对应 `GJailCard.Karma` = `+1 / 0 / -1`
- 教程文案：**"每在狱中待一回合获得 1 点监狱经验"**
- **把当回合所有候选牌都拒绝 = +1 罪恶、刑期 −1**（`CellType_Jail_Decline_Final`）
- 出狱途径：`Amnesty`(Freedom)、`Probation`(PayTerm，按剩余刑期每回合 30$ 赎买
  +1 额外走牌)、上诉掷 4-6、`Perm_Jail` / `Freedom` 等

⚠️ **另注意**：监狱格**自身**的骰子表（被捕时定刑）上限只有
**4 / 3 / 2 次走牌**（`Jail.params=[2,3,4]`），
与上面的 `JAIL_RANK_*_TERM`（5/7/8/10/3）**是两套不同的东西**，极易混淆。

## 七、动作枚举 `EAction`（163 项）

`EAction.cs` 里共 **163** 个动作类型（由 dnSpy 的 RID 11085..11247 计数确认），
是原版动作的**完整清单**。

| 前缀 | 数量 | 含义 |
|---|---|---|
| `Perm_*` | 33 | 永久卡效果 |
| 角色名 `Xxx_*` | 56 | 角色能力 |
| 其余 | 74 | 通用动作（选择、资源、移动、站点…） |

**关键发现**：卡牌数据里实际只用到 **143** 种，
另外 **20 种**是**引擎内部直接引用**、不写进卡牌 `ActionList` 的：

```
None, UseCellEarly, Proceed, InstantConflict, MFProceed, JailProceed,
PlayAnyCard, OpenDialog, Tut_*（3 个）, StartGame, ExitGame,
Politician_Loyal_Electorate, Politician_Astral_Club, Politician_Connections,
Politician_Breathing_Tax, Banker_Old_Investments, Banker_Bank_Account,
Banker_Money_Makes_Money
```

其中 `Politician_Breathing_Tax`（呼吸税）与 `Politician_Loyal_Electorate`
是**引擎在 `GetBribe()` 等函数里直接按角色名调用的**——它们没有对应的卡牌，
所以之前"49 条角色能力"的说法**漏掉了这类不挂在角色 `ActionList` 上的能力**。

完整清单见 [`动作清单.md`](动作清单.md)。
