## 二、`ChangeRes` 的统一语义

所有资源的增减都走同一个函数，规则一致：

```csharp
case GResourceType.Xxx:
    if (Resources.Xxx + value < 0)
        value = -Resources.Xxx;        // ← 夹到 0：不允许为负
    if (value != 0)
    {
        Resources.Xxx += value;        // ← 实际生效的是**夹取后**的 value
        ...
    }
    break;
```

**要点**：
1. **所有资源都不会变成负数**——不足时夹到 0，只扣到 0 为止。
2. 函数**返回实际生效的增减量**（夹取后的 `value`），调用方常依赖它
   （例如「付 X 得 Y」类效果按实付计算）。
3. 资源没有上限（金钱/罪恶/齿轮都可以无限增长）。

### 2.1 收入（`Income`）的特例：不会为负 + 银行家能力

```csharp
case GResourceType.Income:
    if (Resources.Income + value < 0)
    {
        flag = false;                       // ← 注意：置 false
        value = -Resources.Income;          // 夹到 0
    }
    // 银行家「钱生钱」：**只有"真正增加"（flag 仍为 true）时才触发**
    if (CharPerks && 角色 == "Banker" && value > 0 && flag)
        value += param(Banker_Money_Makes_Money_2, 3, 2);   // 默认 +3

    if (value != 0) Resources.Income += value;
    break;
```

⚠️ 这里是**递归式**加成的：因为 `value` 被改大后再写回。
另外 `flag` 的语义是"这次收入变化没有被夹取过"——
**被夹取过就不再触发银行家加成**。（用于「慈善」这类 `Income -N` 的效果。）

### 2.2 刑期（`Term`）与监狱 rank（`JailRank`）

```csharp
case GResourceType.Term:
    if (Resources.Term + value < 0) value = -Resources.Term;   // 夹到 0
    if (value != 0)
    {
        Resources.Term += value;
        // ★ 刑期达到"当前 rank 的上限"时，rank 提升（不是释放！）
        if (Resources.Term >= GetTermLimit())
        {
            Resources.Term -= GetTermLimit();
            if (JailRank < 4) JailRank++;
            else ChangeRes(GResourceType.Score, 1);   // rank 已满 → +1 齿轮
        }
    }
    break;
```

**这是监狱系统的核心，我之前的实现完全理解错了。** 正确语义：

- 刑期 `Term` **累加**，达到 `GetTermLimit()` 就**扣掉一个上限并提升 `JailRank`**；
- `JailRank` 5 档（0..4），对应刑期上限 **5 / 7 / 8 / 10 / 3**；
- **rank 已满（=4）时再加刑期 → 换成 +1 齿轮**（关到底就是"白坐牢"变奖励）；
- 每个服刑回合可抽的监狱牌数 `GetJailCardLimit()` = **2 / 2 / 3 / 3 / 4**；
- **释放**不靠"刑期归零"，而靠监狱卡的效果（`Freedom` / `PayTerm` 等）。

### 3.0 `PayResource` —— 玩家之间的资源转移

```csharp
public bool PayResource(GResourceType resType, int value, GPlayer opponent, out int paid)
{
    GPlayer payer = opponent, payee = this;
    if (value < 0) { payer = this; payee = opponent; value = -value; }   // 负数 = 反向
    ...
    if (payer.Resources.X < value) { flag = false; value = payer.Resources.X; }  // 夹取
    payee.Resources.X += value;
    payer.Resources.X -= value;
    paid = value;                     // ← 输出**实付**
    return flag;                      // ← 返回"是否全额付清"
}
```

**要点**：

1. 这是**转移**（payer 扣、payee 加），不是销毁。用于「某玩家给你 $」这类效果。
2. `value < 0` 时**方向反转**（`this` 变付款方）——所以卡牌里负数参数表示"我付给对手"。
3. 付不起时**夹到付款方全部余额**，`paid` 输出实际转移量。
4. **返回 `bool` 表示是否全额付清**——很多卡牌的"若无法全额支付则…"分支
   就是靠这个返回值判断的。

这解释了为什么卡牌数据里同一动作既有正数也有负数参数
（例如 `OpponentLoseMoney(-1,...)` 表示方向反转）。

num  = Resources.Income;
